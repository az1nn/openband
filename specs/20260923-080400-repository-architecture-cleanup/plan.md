# Plan: Repository Architecture and Folder Cleanup

## Architecture assessment

The repository currently contains one canonical TypeScript backend used by the serverless adapter and CI plus a separate, unreferenced Python microservice prototype. The cleanup removes only the duplicate inactive boundary and tracked artifacts proven to be scratch output, generated media, or superseded documentation. No live application module boundary is moved.

ADR: NOT REQUIRED

The durable architecture remains unchanged: Expo/React frontend under `app/` and `src/`, runtime-specific access through the bridge, the TypeScript service under `backend/`, native projects under `android/` and `electron/`, and repository-owned Spec Kit/Graph governance.

## Deletion set

High-confidence removals proven by reference, ownership, duplicate-content, and history audits:

- `diff.txt`
- `diff_utf8.txt`
- `image.png`
- every tracked file under `openband-backend/`
- `docs/vitest-ui-dashboard.png` — generated by `scripts/screenshot-vitest-ui.mjs`; the tracked snapshot is not a source input and is now ignored
- `docs/openband_product_design_marketing_documentation.pdf` — unreferenced one-off binary upload superseded by repository-owned product/marketing docs
- `docs/device-bridges.html` — unreferenced duplicate guide superseded by `docs/architecture.md` and bridge source
- `docs/future-roadmap.html` — unreferenced stale future-plan export superseded by `ROADMAP.md` / `docs/roadmap.md`

Intentional compatibility shims such as `CLAUDE.md`, `docs/graph-engineer.html`, and `docs/graph-engineer-devguide.md` remain because they delegate to canonical sources rather than duplicate authority.

## Explicit non-goals

- no dependency-version or lockfile churn;
- no Android signing/security repair (owned by existing work);
- no native build scheduler changes;
- no deletion of marketing screenshots/knowledge, agent compatibility paths, Spec Kit files, Storybook stories, WASM assets, or release assets while they remain referenced;
- no product feature refactor.

## Verification

Before deletion:

- repository tree audit for generated/vendor/temp artifacts;
- reference search for every deletion candidate;
- duplicate-blob audit;
- history/ownership review for unreferenced documentation artifacts;
- confirm the canonical backend and tool-owned directories are still live;
- design candidate passes SDD/Graph policy, security policy, frontend/backend typecheck, legacy tests and Web build.

After deletion:

- negative repository-tree/reference audit for removed surfaces;
- `npm run sdd:check`;
- `npm run test:graph-sdd`;
- `npm run graph:ci`;
- frontend and backend typechecks;
- full Vitest and legacy tests;
- Web export build;
- launch Playwright E2E;
- security policy;
- exact-HEAD evidence-driven Merge Gate.

Rollback is the branch parent commit; no production data or runtime mutation is involved.

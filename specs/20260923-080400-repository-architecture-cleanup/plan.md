# Plan: Repository Architecture and Folder Cleanup

## Architecture assessment

The repository has one canonical TypeScript backend used by the serverless adapter and CI plus an unreferenced Python prototype tree and a set of tracked artifacts proven to be scratch output, generated media, superseded documentation, or zero-consumer source. No live application module boundary is moved.

ADR: NOT REQUIRED

The durable architecture remains unchanged: Expo/React frontend under `app/` and `src/`, runtime-specific access through the bridge, the TypeScript service under `backend/`, native projects under `android/` and `electron/`, and repository-owned Spec Kit/Graph governance.

### Architecture Graph orphan classification

The design/final Graph run reported 46 `OB-GRAPH-004` orphan-source candidates. The warning alone is not deletion proof: it also reports legitimate runtime entrypoints such as `backend/src/index.ts`, `electron/main.js`, and `electron/preload.js`, and it reports test-backed or normative modules.

A second reference/role audit removes only sources with **no production importer, no test consumer, no self-registration, no package/runtime entrypoint, and no normative-contract ownership**:

- `src/hooks/useAutoPush.ts` — superseded by `src/lib/cloudSync.ts::useCloudSync`
- `src/hooks/useVoiceControl.ts`
- `src/lib/arrangement.ts` — unused re-export shim over `arrangementGenerator.ts`
- `src/lib/chunkedRenderer.ts` — unused parallel renderer; active mixdown stays in `universalAudio.ts` / current render paths
- `src/lib/habboAssets.ts`
- `src/lib/lazyDrumKit.ts`
- `src/lib/synth/junoEngine.ts`
- `src/lib/synth/tritonEngine.ts`
- `backend/src/workers/assetConsolidation.ts`
- `backend/src/workers/cleanupTrash.ts`

The stale extracted `.qwen/skills/auto-skill-cloud-sync-auto-push/SKILL.md` is also removed because it duplicates the superseding `cloudSync.ts` implementation. The native mixdown skill is retained but reconciled to the canonical `universalAudio.ts` path.

Graph candidates that are test-backed, contract-backed, explicit entrypoints, or otherwise intentionally owned are preserved. Cleanup does not reduce tests merely to make orphan warnings disappear.

Intentional compatibility shims such as `CLAUDE.md`, `docs/graph-engineer.html`, and `docs/graph-engineer-devguide.md` remain because they delegate to canonical sources rather than duplicate authority.

## Explicit non-goals

- no dependency-version or lockfile churn;
- no Android signing/security repair (owned by existing work);
- no native build scheduler changes;
- no deletion of marketing screenshots/knowledge, agent compatibility paths, Spec Kit files, Storybook stories, WASM assets, or release assets while they remain referenced;
- no removal of test-backed or normative code solely because the Graph has no production inbound edge;
- no product feature refactor.

## Verification

Before destructive changes:

- repository tree audit for generated/vendor/temp artifacts;
- reference search for every deletion candidate;
- duplicate-blob audit;
- history/ownership review for unreferenced documentation artifacts;
- Architecture Graph orphan classification;
- confirm the canonical backend and tool-owned directories are live;
- design candidate passes SDD/Graph policy, security policy, frontend/backend typecheck, legacy tests, Vitest, Web build, launch E2E, and Merge Gate.

After cleanup:

- negative repository-tree/reference audit for removed surfaces;
- `npm run sdd:check`;
- `npm run test:graph-sdd`;
- `npm run graph:ci`;
- frontend and backend typechecks;
- full Vitest and legacy tests;
- Web export build;
- launch Playwright E2E;
- security policy;
- exact-HEAD evidence-driven Merge Gate.

Rollback is the branch parent commit; no production data or runtime mutation is involved.
